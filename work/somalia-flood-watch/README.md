# El Nino Watch

Extract the package and run `Start-Live-App.ps1` on Windows, or run `node server.mjs` from this directory. Open http://127.0.0.1:4173 and keep the server running. Node.js 22 or newer (Node.js 24 recommended) and internet access are required. No package installation or API keys are needed. The server listens only on your computer.

The app connects live to Open-Meteo weather, GloFAS river forecasts, Copernicus satellite acquisitions, GDACS Somalia flood events, ICPAC weekly exceptional rainfall forecasts, NOAA ENSO, SWALIM river gauges, Copernicus CEMS radar flood classifications and NASA satellite flood composites. It refreshes on opening, every 15 minutes while visible, when returning to an overdue tab and when the internet connection resumes. Weather and river forecasts cover 44 cities over a rolling 14-day window in Somalia time. Source issue/observation dates and retrieval times are shown separately. Downloaded CSV files contain 420 city/date rows, with missing values left blank and stale flags included.

Opening `dist/index.html` directly connects only the browser-accessible feeds. Use the local Node server for community reports, uploads, comments, NOAA, SWALIM, official warnings, the Copernicus city catalogue and observation metadata / point queries. The standalone file:// HTML needs that server for the catalogue feature. Keep the app window open for automatic updates; the package does not run a background monitor. Opt-in browser notifications work while the app is open and require browser permission.

NOAA ENSO and FAO SWALIM gauge data use a local, fixed-source relay because their public websites may block direct browser requests. The relay caches successful responses for ten minutes and retains earlier readings with a stale label if an update fails. No keys or accounts are needed for these feeds. Missing measurements remain unavailable.

Gauge dates are source observation dates, not request times. Gauge heights and station-specific flood thresholds are distinct from modeled river discharge. A river alert does not establish flooded area or affected population. The weekly conventional Niño 3.4 anomaly is distinct from the three-month RONI index in NOAA's official ENSO assessment.

## Copernicus city catalogue API

GET /api/copernicus?city=city-slug queries the public Copernicus Data Space STAC catalogue for Sentinel-1 GRD radar and Sentinel-2 L2A optical acquisitions from the last 14 days. It searches the selected city's approximate centre bounding box, extending 0.1 degrees in each direction, and returns up to eight recent acquisitions per mission. City coordinates describe a surrounding search area rather than a city boundary. Optical scene cloud percentages describe the whole scene; an unknown percentage remains unknown, and radar does not use an optical cloud percentage.

The two mission queries fail independently: a working radar feed remains available when the optical query fails, and vice versa. The server caches successful city responses for ten minutes; the app refreshes every 15 minutes while visible. Acquisition times describe when the satellite observed the scene, while retrieval times describe when the app fetched its metadata. An available or recent acquisition alone does not identify flooded streets or verify flood damage, and no returned scenes does not establish that an area is dry. Confirmed impact should come from source reports, with their event dates and geographic coverage shown.

Catalogue queries work without an account or key. The app uses the existing public, dated CEMS Global Flood Monitoring classification service separately for observed water. Custom Sentinel-1/Sentinel-2 pixel processing through Sentinel Hub requires a Copernicus Data Space account and secure server-side OAuth credentials and is not activated in this package. No credentials belong in the page, downloads or public client code. API documentation: https://documentation.dataspace.copernicus.eu/APIs/STAC.html and https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Process.html.

Map links into Copernicus Browser include both UTC start and end times. When a city has a returned optical acquisition, the link opens that acquisition's day; otherwise it opens the previous 14 days through the current time. Forecast dates are kept separate and are never used as future satellite observations. Links start from a fresh Browser URL without an inherited saved visualization. The displayed observation window includes cloudy scenes; cloud cover and imagery brightness do not establish flooding. For an existing Browser page with an empty date, choose a date or use **Show latest date**.

## Dated observed flood water and API alerts

The map opens on Mogadishu with the Copernicus CEMS Global Flood Monitoring Sentinel-1 radar layer enabled. Magenta pixels are satellite-classified flood water at 20 m; acquisition footprints show coverage, not flooded area. The observation date is separate from the forecast day. The default date comes from live service capabilities and selects the latest completed UTC day. Today is selectable with a partial-coverage label. The optional NASA MODIS layer shows a three-day, 250 m composite: red flood detection, yellow recurring flooding, cyan reference water, gray insufficient observations. Enlarging pixels does not add detail.

Click a city or point to check dated radar coverage, flood classification, exclusion and reference-water masks. The optional exclusion-mask toggle shows areas excluded from automatic classification; these are unknown areas, not evidence of dry ground. Urban, vegetation or insensitive pixels can be unknown even within a scene footprint. Missing masks, absent scenes and failed queries remain unknown. Satellite classifications are not ground-confirmed incidents or proof that water remains present. No city inundated-area or affected-population totals are inferred.

Alert coverage opens on All 44 cities; choose Selected city to narrow it. Regional rainfall forecasts come from ICPAC (IGAD Climate Prediction and Applications Centre): its weekly exceptional rainfall forecast is checked at each of the 44 cities, and a city above the 90th, 95th or 99th percentile for that week of the year gets a heavy, very heavy or extremely heavy rainfall alert for the forecast week. These are regional model forecasts, not official warnings; the app has no official national warning source. GDACS event/model signals are labeled separately. Only the current forecast week appears as active; the issue date is shown in status. The flood map can show ICPAC's heavy-rain areas and weekly totals for the same week. Source notices, observed station thresholds and app-defined rainfall screens have separate badges. City filters do not invent a city extent for country-level notices. App rainfall screens cover the next three calendar days, including full today. Hypothetical exercises cannot generate official alerts.

API routes are /api/copernicus?city=city-slug, /api/alerts, /api/observed-flood, /api/observed-point?lat=…&lon=…&date=YYYY-MM-DD, /api/enso, /api/stations and /api/hazard-point?lat=…&lon=…. The observed-flood route supplies live capabilities and dates for the separate CEMS GFM map masks. Relays use fixed public sources, no accounts or keys. Recent retrieval does not mean a new source issue. Failed refreshes retain last-known data with a stale label; stale data cannot trigger active alerts. Browser notifications are off until enabled by the user, respect the selected scope and type, and deduplicate repeated signals. They work only while this page is open.

ICPAC weekly forecast: https://www.icpac.net/weekly-forecast/. East Africa Hazards Watch: https://eahazardswatch.icpac.net/ (dataset list /api/datasets/, map server /mapserver/). Radar methodology: https://extwiki.eodc.eu/gfm_assets/gfm4.0_pum_2025.pdf. NASA methodology: https://www.earthdata.nasa.gov/global-flood-product.

The supplied Copernicus Browser true-colour view is a dated Sentinel-2 scene, not an alert feed. Public catalogue metadata and the separate public CEMS radar WMS API work here without credentials. Accessing raw Sentinel-2 processing through Copernicus Sentinel Hub is a different API that requires account credentials.

## Community reporting, media and comments

The community panel accepts reports by city, observation time in East Africa time, flooding/rain/damage category, description, optional alias, source link and coordinates. Deaths, injuries and damaged-property counts are separate nullable values: blank means unknown and zero is an explicitly entered zero. Reports and comments are unverified, and casualty totals are not summed because submissions can overlap or duplicate the same incident. This app does not replace emergency services.

Upload up to four JPEG, PNG, WebP, GIF, MP4 or WebM files, totaling at most 50 MiB. File contents are checked on the server; SVG and executable/HTML uploads are rejected. Uploaded originals may preserve identifying metadata. Choose what to share before submitting. Media and optional coordinates are visible to people who can access this app. Videos support inline playback and byte ranges. A selected map point can fill report coordinates, and device location is requested only after clicking its button.

Comments appear under each report. A random deletion receipt is saved in the submitting browser; it allows its owner to remove the report, media and comments. There is no identity verification or administrator moderation console. All records remain labeled unverified. Lost browser storage can mean losing deletion access. Published sources, observation time, received time and optional coordinates are visible, and CSV/GeoJSON exports retain the unverified status and unknown values. Located reports appear as purple point markers, not flood boundaries; reports without coordinates are not assigned an invented location.

Records and media persist in the server's data directory outside dist, surviving reloads and restarts. Back up that directory separately. COMMUNITY_DATA_DIR can override its location; local data and deletion receipt hashes are excluded from the download ZIP. The package contains no sample or invented community events. Directly opening the standalone HTML cannot publish shared records; start the Node server for the full app. The default server listens on this computer only. The footer domain elninowatch.so is a contact/brand link and has not been connected to this local server.

For a phone on the same trusted network, run the server with HOST=0.0.0.0 and open the computer's LAN address on port 4173. In PowerShell: $env:HOST='0.0.0.0'; node server.mjs. The default remains loopback. Device geolocation and clipboard permissions depend on browser security; manual coordinates and links remain usable. Internet/public hosting requires a Node-compatible server, persistent storage, HTTPS and a domain configuration. No public hosting or DNS change is included in this local package.

Community API: GET /api/community/reports?city=city-slug; POST /api/community/reports (multipart payload JSON plus media); POST /api/community/reports/{id}/comments (JSON); DELETE /api/community/reports/{id} (deletion receipt); GET /api/community/media/{id}. Writes validate origin, city, dates, coordinates and size and use bounded rate limits. Private data files cannot be served through the static path.

## Independent service and terrain inspection

El Nino Watch is an independent, non-government information service. Information comes from public-domain and other publicly available sources, with source-specific licences and terms. Public availability does not transfer all copyright: Natural Earth is public domain; Open-Meteo data use CC BY 4.0; SWALIM metadata does not specify a general licence; contributed media keep their own rights. For emergencies and support, contact your local government offices and/or the relevant authority in your area. The notice appears above the dashboard and again in the footer.

Rainfall screening counts cities with at least one forecast day of 10 mm or more across the 14-day window, using only complete forecasts. The watchlist has two groups of 15 cities, with search and selection preserved; groups stack on smaller screens. Screening badges retain their existing bands: Lower below 10 mm/day, Watch 10–24.9 mm/day, Elevated 25 mm/day or more. These thresholds are app screening rules, not official flood probabilities.

The low-lying terrain panel shows the SWALIM 30 m susceptibility layer by default. Its height-above-drainage, slope, depression and flow-path model identifies ground to inspect without applying an arbitrary absolute-elevation cutoff. Orange/red ground cells have higher terrain potential; city dots use rainfall/gauge screening, and satellite flood classifications remain a separate observation layer. The highlight control turns on susceptibility and historical footprints, focuses a city and brings the map into view. Click a point or check a city-centre point to see the returned terrain class, separate 90 m DEM elevation and historical feature result. A city-centre sample represents one cell, not the whole city. Missing classes remain unavailable and lower classes do not prove safety.

The Juba and Shabelle floodplains are established areas for flood-risk inspection, including locally low ground beside river channels. Inland seasonal channels and depressions can also experience flash flooding. Evidence source: https://faoswalim.org/content/w-15-flood-risk-and-response-management. The terrain map and historical layer do not show current flood water, predicted depth or an engineering design.

Source terms: https://www.naturalearthdata.com/about/terms-of-use/ and https://open-meteo.com/en/terms. Terrain source: https://spatial.faoswalim.org/catalogue/#/dataset/609.

## Additional cities and two-week flood planning

The **Additional cities** button opens a separate dialog. Add a name and optional region, then find coordinates from Somali populated-place results in Open-Meteo/GeoNames or enter them manually. A name can be saved without coordinates; forecasts remain unavailable until both latitude and longitude are supplied. Edit or remove saved entries from the dialog. Duplicate checks compare normalized names, common spelling variants and coordinates within 2 km against both the original 44 cities and other saved additions. The original selectors, map city markers and 44-city forecast batch are not expanded.

Additional-city names and coordinates stay on this device in `somalia-extra-cities-v1`; storage failures retain entries in memory with a visible notice. Added locations appear only in their dialog list, where coordinate-based outlooks can be loaded. Official city warnings, community reporting, matched gauges and satellite queries remain connected to the original monitored cities. Manual coordinates pass a Somalia-area bounds check but are not verified administrative boundaries.

The new **14-day flood planning outlook** combines date-aligned rainfall forecasts and GloFAS modeled river discharge, showing daily selections, separate week-one/week-two summaries, missing-data gaps and CSV exports. Rainfall uses EAT days; discharge uses UTC model days, so their 24-hour periods differ. Retrieval dates and stale responses remain independent for both feeds, and days 8–14 carry lower confidence. Incomplete weekly data do not produce invented totals. Viewed additional-city outlooks refresh every 15 minutes while their dialog is open and refresh after reconnection or resuming an expired view.

Rainfall colours use app screening levels of ≥10 and ≥25 mm/day; river trends compare with the first model day. No city-specific discharge threshold, inundation footprint, depth, casualty forecast or calibrated flood probability is inferred. The river model has an approximately 5 km grid, and its chosen cell may differ from the local channel. A zero discharge or low rainfall value does not establish safety. The supplied SWALIM image covers 6–12 October 2026 and remains a dated reference, rather than the next 14 days of data.

Sources: https://open-meteo.com/en/docs/flood-api and https://open-meteo.com/en/docs/geocoding-api.

## Top-five city comparisons

The overview and mayor tools include four responsive comparison cards for the original 44 monitored cities. Additional cities remain separate. Rainfall rankings use the existing live weather feed: today's **full-day forecast** in EAT, and the accumulated forecast for **tomorrow through the following six days** (seven complete EAT dates). They are not observed rain-gauge totals. Missing or incomplete values are excluded, source coverage and retrieval times are shown, and failed refreshes retain dated last-known values with a stale label. Equal values are ordered alphabetically.

Current feeds do not quantify comparable flooded area or depth for all 44 cities, or provide calibrated city inundation forecasts. The **Flooding today** card therefore compares **unverified community flood-report activity**, not flood severity, using a separate all-city report request and observation dates in EAT. Rain-only and damage reports, future observations, unknown cities and duplicate report IDs are excluded. No report is not evidence of a dry city. A truncated report response cannot support all-city counts; the ranking stays unavailable rather than presenting incomplete totals.

The **Flood watch · next 7 days** card lists rainfall-based planning priorities among cities with complete seven-day forecasts and at least one day of ≥10 mm. Cities are ordered by peak daily rainfall, then the number of days meeting that screen, then total rainfall. It is not a ranking of predicted flood extent or a calibrated flood probability. River conditions, upstream rain, terrain, drainage and field evidence still need review. Each city opens the appropriate detailed weather, reporting or flood map tool. The lists follow today's date and do not change when a different forecast day or exercise scenario is selected.

## Mayor dashboard

The home page opens on the **All 44 cities** overview, with the original 44-city watchlist and all-city alert coverage. The default map shows all 44 cities; Mogadishu remains the initial city for detailed forecasts. Additional cities stay in their separate dialog. Select **Mayor dashboard** in the navigation or open `#city=Galkayo&view=mayor` for a city leadership briefing. A city-only link such as `#city=Galkayo` selects that city within the overview. The mayor dashboard is an independent planning view, not an authenticated municipal system or an official government dashboard.

Weather, flood maps, alerts and reporting are available in the overview and as focused tools from the mayor dashboard or navigation. Focused tools retain a **Mayor dashboard** return button. **All 44 cities** in the header or the **44 cities** mobile tab returns to the overview and all-city alert coverage. The selected city, forecast date and local planning actions stay available when moving between views. The map tool uses the full width.

The briefing combines the operational next three days in East Africa time, the 14-day forecast, city-relevant official notices and Somalia-wide notices with unspecified city extent, matched river observations, Copernicus acquisition dates and satellite product coverage limitations. Missing values and stale sources remain labelled. Satellite product availability does not establish a city-wide flood footprint or a safe route.

Its community queue uses a separate city-scoped request, unaffected by the reporting tool's category or coverage filters. Reports remain unverified. Impact counts appear per report with blank values unknown; overlapping deaths, injuries and property counts are not summed. The report service returns up to 200 newest records, with total and truncation status retained.

Create local actions with an owner, due date and priority, then move them through to-do, in-progress, blocked and done. Report review labels record follow-up progress only; they never verify or change a public report. Actions and review notes are stored in this browser on this device under `somalia-city-manager-v1`, separately for each city. They are not shared with other users and do not send messages or emergency dispatches. A storage failure is visible and preserves changes in memory until the page closes. Export a briefing or actions for a handoff.

## Explore and plan

The navy and blue daily-weather panel opens on Mogadishu unless a city is selected in the URL. Choose any of the 44 cities, then one of the 14 day cards. Click an hour card or the meteogram to inspect that hour. Daily summaries include high/low and feels-like temperature, rainfall and maximum rain probability, wind/gusts, sunrise/sunset and UV. The 24-hour chart and expandable table add humidity, cloud cover, pressure, visibility and dew point. Export the selected day's 24-hour CSV with its source retrieval time. Detailed forecasts refresh automatically and are cached separately for each city; unavailable fields and stale responses stay labeled.

Live detailed values come from Open-Meteo with explicit Celsius, km/h, millimetres and Somalia UTC+3 settings. The linked meteoblue Gaalkacyo page is an external comparison, not a source copied into this app.

Select a city using the map markers, city list or city dropdown. Use the 14-day slider or rainfall bars to inspect a day. The overview button returns to all cities. City colors indicate selected-day rainfall screening and recent SWALIM river thresholds; stale or undated gauge data never trigger a red marker.

Toggle official SWALIM layers for 30 m terrain flood susceptibility, mapped historical flood extents (2013–2023), Shabelle bank breakages (August 2026 assessment), and Juba bank breakages (March 2026 assessment). Each layer keeps its official legend and date. Click a map point for its DEM elevation, susceptibility class, historical layer result and any nearby dated bank records. These are screening and historical datasets, not current water depth or inundation. Low or absent features do not prove safety.

Choose live conditions, heavy rain, rising river or blocked-drain exercises to get a city planning checklist. Exercises are hypothetical and leave live forecasts and CSV values unchanged. Download the planning checklist for source links and dated evidence. Water-diversion options require surveyed levels, hydraulic modelling, agency and engineer review, consultation and permits; this app supplies no construction route or dimensions.

Terrain source: https://spatial.faoswalim.org/catalogue/#/dataset/609. Historical flood-prone source: https://spatial.faoswalim.org/catalogue/#/dataset/295. Point elevation: Copernicus DEM GLO-90 via Open-Meteo (90 m; https://open-meteo.com/en/docs/elevation-api). Basemap: bundled Natural Earth 1:10 million regional countries and rivers, public domain (https://www.naturalearthdata.com/about/terms-of-use/). It uses no external basemap tile service or API key. It is generalized reference geography, with no current street or road-navigation detail. Blue river lines are reference features, not current flood extent. SWALIM overlays still need internet access. SWALIM catalogue licence is not specified; public service access is verified, and additional reuse terms should be checked with SWALIM.

## English and Somali

Use **EN** or **SO** in the header to switch the interface between English and standard Somali. The choice is saved on this device and can be shared with `?lang=en` or `?lang=so`, preserving the selected city and dashboard link. When browser storage is unavailable, the language remains selected for this page and the app shows a notice. All translation assets are bundled locally; switching language sends no text or reports to an external translation service.

The curated Somali catalog covers navigation, forecasts, alerts, map legends, Mayor planning, additional cities, forms, accessibility labels, errors, safety guidance and the independent-service disclaimer. Critical meanings were reviewed separately against the English source, with [FAO SWALIM Somali flood guidance](https://faoswalim.org/so/lasocod-fatahaad) as a terminology reference. User-entered reports, comments, names, files, planning text, provider-authored notices and source quotations retain their original wording. Labels change, while IDs, coordinates, values, dates, selected filters and entered form data stay intact. Human daily briefings and downloaded planning checklists use the selected language at download time. Structured data exports retain stable English column names for compatibility.
